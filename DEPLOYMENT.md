# PrivacyGuard Deployment Guide

Guide for deploying PrivacyGuard to production.

## Overview

PrivacyGuard consists of three deployable components:

1. **Backend API** (Node.js + PostgreSQL)
2. **Frontend Web App** (React SPA)
3. **Browser Extension** (Chrome/Firefox stores)

## Prerequisites

- Domain name (e.g., privacyguard.com)
- SSL certificate (automatic with most hosts)
- PostgreSQL database (managed service recommended)
- HaveIBeenPwned API key (optional but recommended)

## Option 1: Quick Deploy (Recommended)

### Backend: Railway

[Railway](https://railway.app) provides easy Node.js + PostgreSQL deployment.

1. **Create Railway account**
2. **New Project** → **Deploy from GitHub**
3. **Add PostgreSQL** service
4. **Configure environment variables**:
   \`\`\`
   DATABASE_URL=<auto-generated>
   JWT_SECRET=<generate-random-string>
   NODE_ENV=production
   HIBP_API_KEY=<your-key>
   CLIENT_URL=https://your-domain.com
   \`\`\`
5. **Deploy**: Railway auto-deploys on git push

**Cost**: ~$5-10/month

### Frontend: Vercel

[Vercel](https://vercel.com) is perfect for React apps.

1. **Create Vercel account**
2. **Import Git Repository**
3. **Configure**:
   - Root Directory: `client`
   - Build Command: `npm run build`
   - Output Directory: `dist`
4. **Environment Variables**:
   \`\`\`
   VITE_API_URL=https://your-api.railway.app/api
   \`\`\`
5. **Deploy**: Auto-deploys on git push

**Cost**: Free for personal projects

### Database: Railway PostgreSQL

Included with Railway backend deployment.

**Alternative managed databases**:
- [Supabase](https://supabase.com) — Free tier available
- [Neon](https://neon.tech) — Serverless PostgreSQL
- [Heroku Postgres](https://heroku.com/postgres)

## Option 2: Traditional VPS

### Backend on VPS (DigitalOcean, Linode, AWS EC2)

\`\`\`bash
# 1. SSH into server
ssh user@your-server-ip

# 2. Install Node.js 18+
curl -fsSL https://deb.nodesource.com/setup_18.x | sudo -E bash -
sudo apt-get install -y nodejs

# 3. Install PostgreSQL
sudo apt install postgresql postgresql-contrib

# 4. Clone repository
git clone https://github.com/yourusername/privacyguard.git
cd privacyguard/server

# 5. Install dependencies
npm install --production

# 6. Setup environment
cp .env.example .env
nano .env  # Edit with production values

# 7. Run migrations
npm run prisma:migrate

# 8. Install PM2 (process manager)
sudo npm install -g pm2

# 9. Start server
pm2 start index.js --name privacyguard-api
pm2 save
pm2 startup

# 10. Setup Nginx reverse proxy
sudo apt install nginx
sudo nano /etc/nginx/sites-available/privacyguard
\`\`\`

**Nginx config**:
\`\`\`nginx
server {
    listen 80;
    server_name api.privacyguard.com;

    location / {
        proxy_pass http://localhost:3001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
    }
}
\`\`\`

\`\`\`bash
# Enable site
sudo ln -s /etc/nginx/sites-available/privacyguard /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx

# Setup SSL with Let's Encrypt
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d api.privacyguard.com
\`\`\`

### Frontend on VPS

\`\`\`bash
# 1. Build locally
cd client
npm run build

# 2. Upload dist/ folder to server
scp -r dist/* user@server:/var/www/privacyguard

# 3. Configure Nginx
sudo nano /etc/nginx/sites-available/privacyguard-frontend
\`\`\`

**Nginx config**:
\`\`\`nginx
server {
    listen 80;
    server_name privacyguard.com www.privacyguard.com;
    root /var/www/privacyguard;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }
}
\`\`\`

\`\`\`bash
# Enable and restart
sudo ln -s /etc/nginx/sites-available/privacyguard-frontend /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx

# Setup SSL
sudo certbot --nginx -d privacyguard.com -d www.privacyguard.com
\`\`\`

## Option 3: Docker Deployment

### Docker Compose

Create `docker-compose.yml`:

\`\`\`yaml
version: '3.8'

services:
  postgres:
    image: postgres:14
    environment:
      POSTGRES_DB: privacyguard
      POSTGRES_USER: privacyguard
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    ports:
      - "5432:5432"

  backend:
    build: ./server
    environment:
      DATABASE_URL: postgresql://privacyguard:${DB_PASSWORD}@postgres:5432/privacyguard
      JWT_SECRET: ${JWT_SECRET}
      NODE_ENV: production
    ports:
      - "3001:3001"
    depends_on:
      - postgres

  frontend:
    build: ./client
    ports:
      - "80:80"
    depends_on:
      - backend

volumes:
  postgres_data:
\`\`\`

**Deploy**:
\`\`\`bash
docker-compose up -d
\`\`\`

## Browser Extension Deployment

### Chrome Web Store

1. **Create developer account** ($5 one-time fee)
2. **Prepare extension**:
   \`\`\`bash
   cd extension
   # Add real icon files to icons/
   # Update manifest.json with production API URL
   zip -r privacyguard-extension.zip *
   \`\`\`
3. **Upload to Chrome Web Store**:
   - Go to [Chrome Web Store Developer Dashboard](https://chrome.google.com/webstore/devconsole)
   - Click "New Item"
   - Upload ZIP file
   - Fill in store listing (description, screenshots, etc.)
   - Submit for review (1-3 days)

### Firefox Add-ons

1. **Create developer account** (free)
2. **Prepare extension** (same ZIP as Chrome)
3. **Upload to Firefox Add-ons**:
   - Go to [Firefox Add-on Developer Hub](https://addons.mozilla.org/developers/)
   - Submit New Add-on
   - Upload ZIP
   - Fill in listing
   - Submit for review (1-7 days)

## Security Checklist

- [ ] Use strong JWT_SECRET (64+ characters)
- [ ] Enable HTTPS/SSL on all domains
- [ ] Set secure CORS origins (no wildcards)
- [ ] Use environment variables (never commit secrets)
- [ ] Enable PostgreSQL SSL connection
- [ ] Set up database backups
- [ ] Configure rate limiting
- [ ] Enable security headers (helmet.js)
- [ ] Set up monitoring (Sentry, LogRocket)
- [ ] Configure firewall rules

## Monitoring & Logging

### Backend Monitoring

**Recommended tools**:
- [Sentry](https://sentry.io) — Error tracking
- [LogRocket](https://logrocket.com) — Session replay
- [Datadog](https://datadoghq.com) — Infrastructure monitoring

**Setup Sentry**:
\`\`\`bash
npm install @sentry/node
\`\`\`

\`\`\`javascript
// server/index.js
import * as Sentry from '@sentry/node';

Sentry.init({
  dsn: process.env.SENTRY_DSN,
  environment: process.env.NODE_ENV
});
\`\`\`

### Database Backups

**Automated backups**:
\`\`\`bash
# Daily backup script
#!/bin/bash
pg_dump privacyguard > backup-$(date +%Y%m%d).sql
# Upload to S3 or backup service
\`\`\`

## Performance Optimization

### Backend
- Enable gzip compression
- Add Redis caching for frequent queries
- Use connection pooling
- Optimize database queries

### Frontend
- Enable Vite build optimizations (already configured)
- Use CDN for static assets
- Enable browser caching
- Lazy load routes

### Database
- Add indexes on frequently queried columns
- Regular VACUUM and ANALYZE
- Monitor slow queries

## Scaling

### Horizontal Scaling

**Backend**:
- Deploy multiple instances behind load balancer
- Use Redis for session storage
- Implement rate limiting

**Database**:
- Read replicas for analytics queries
- Connection pooling
- Consider sharding for large datasets

## Rollback Plan

If deployment fails:

1. **Revert code**: `git revert <commit>`
2. **Rollback database**: Restore from backup
3. **Redeploy previous version**
4. **Check logs** for errors
